# Recovery audit: 13 November 2026

## Verified before this patch

The last committed validated refresh is 1 November 2026, with 330 records, 30 documentary reviews and zero independent replications. Both scheduled refresh runs on 8 November failed before reporting any steps. Re-running the failed backup job on 13 November also failed before steps. Logs were unavailable. The connector cannot read the check annotations, so billing, runner availability and policy restrictions remain hypotheses, not diagnosed causes. No billing or spending settings have been changed.

The public search index contains FronteraEval and individual evaluation pages. Indexed pages can have different crawl dates; search snippets are not a production freshness check.

## Narrow recovery changes

- Reapply the six reviewed runtime files from PR 31 onto current main, retaining the newer Evaluation Brief and source registry.

- Run all existing quality gates plus runtime and freshness regression tests in Netlify before publication.
- Recompute freshness when a status endpoint is read. A recent source observation must not mask an old validated catalogue.
- Add `/api/health`: HTTP 503 for stale or unverified publication, HTTP 200 only for a completed validated refresh no older than eight days.
- Public status reads no longer start a crawler.

This patch does not claim to fix that restriction or to have refreshed the catalogue.
