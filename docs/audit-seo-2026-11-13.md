## Correcciones locales

Se recuperaron selectivamente las dos reglas de alias y la metadata útil de PR #30. No se importaron sus páginas generadas ni su caché prolongada de `/api/`, incompatible con la salud actual.

El sitemap incluye Evaluation Brief y su HTML tiene metadata social. Se comprueban todas las fichas, no solo las primeras veinte. Las colisiones de slug fallan antes de eliminar páginas válidas. La reconstrucción elimina fichas retiradas.

El generador ya no usa `generated_at` ni `last_source_check` como fechas de modificación. Se omiten `lastmod`, `dateModified` y `article:modified_time` porque no existe un historial fiable de cambios de contenido de cada página. El feed se identifica explícitamente como revisiones documentales y utiliza únicamente `methodological_review.reviewed_at` válido y conservado. No es un feed de novedades importadas. Recuperar fechas precisas para todas las páginas exige registrar revisiones de contenido, no reutilizar la fecha de descarga.

El runtime SEO captura hashes con codificación inválida y descarta callbacks de sharing de una ficha cuando la ruta ya cambió.

## Reproducción

```sh
# Tras la generación del catálogo, sin volver a descargar upstream:
node scripts/test-discovery.mjs
node --test scripts/test-discovery-dates.mjs

# Auditoría HTTP completa, incluida la página Brief:
node scripts/audit-discovery-live.mjs https://fronteraeval.org /tmp/fronteraeval-seo-live.json
# Para un preview publicado, el mismo comando comprueba también X-Robots-Tag: noindex:
node scripts/audit-discovery-live.mjs https://deploy-preview-34--fronteraeval.netlify.app

# En el entorno de esta sesión, Node 24 necesita el proxy de red habilitado:
NODE_USE_ENV_PROXY=1 node scripts/audit-discovery-live.mjs https://fronteraeval.org
```

Resultados locales ejecutados: `test-discovery.mjs` pasa con 333 registros, 10 temas y 350 URLs tras la reconstrucción del integrador. `test-discovery-dates.mjs` pasa: dos reconstrucciones con distintas fechas de observación generan idénticos sitemap, feed y fichas; se elimina una ficha retirada; un slug duplicado no borra las páginas válidas. Estas pruebas se ejecutaron con Node 24.22.1 en este subtrabajo; la aceptación completa con Node 22 y el commit final corresponde a la integración.

Los cambios locales no equivalen a una publicación. Repetir el auditor contra el preview y producción después del despliegue, y vincular los resultados al SHA que proporcione Netlify.
